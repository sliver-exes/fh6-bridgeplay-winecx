# ws2_32 network fix (FH6 online on the FEX route)

A small `ws2_32.dll` proxy that lets Forza Horizon 6 join online sessions under the Highball arm64 engine (Wine 11.18 + FEX) on macOS.

## The finding

FH6 opens its Xbox Live UDP socket as a dual-stack IPv6 socket on port 3074:

1. `socket(AF_INET6, SOCK_DGRAM)`, `setsockopt(IPV6_V6ONLY = 0)`, bind `[::]:3074`
2. `WSAIoctl(SIO_UDP_NETRESET)`: Wine does not implement it (unsupported)
3. `setsockopt(IPPROTO_IP, IP_DONTFRAGMENT / IP_TTL)`: `WSAEINVAL`, because macOS refuses IPv4-level options on an IPv6 socket

Windows accepts all three. When one fails the game closes the socket, retries on another port and ends up unable to join a session.
A winsock trace of the game showed exactly these calls failing; with the proxy the trace shows them as `forced-success` and the
socket stays open.

## The fix

`ws2_32-fh6.dll` (x64 PE, `../../bin/ws2_32-fh6.dll`) exports every function of the runner's `ws2_32.dll` (136 names, same ordinals) and
forwards them to a renamed copy of the runner's own builtin, `ws2_o.dll`. It wraps `socket`, `WSASocketW`, `WSASocketA`, `WSAIoctl`,
`setsockopt` and `closesocket`, tracks the UDP `AF_INET6` sockets, reports `SIO_UDP_NETRESET` as success, and when an `IPPROTO_IP`
`setsockopt` fails on a tracked socket it applies the IPv6 equivalent first and reports success. A Wine registry override
(`AppDefaults\forzahorizon6.exe\DllOverrides`) makes only `forzahorizon6.exe` load the proxy.

## Environment variables

Set as Steam launch options with the `NOTPROTON_ENV_` prefix.

| Variable | Effect |
|---|---|
| `MGF_FH5_NETFIX=0` | Turn the fixes off (pure pass-through), for A/B tests |
| `MGF_FH5_NETLOG=1` | Write `fh6-netfix.log` in the game folder (the process working directory) |

## Files

- `../../src/fh6-netfix.c`: the proxy source (freestanding, kernel32 only). `../../src/fh6-vs-upstream.diff` is the diff to the upstream file.
- `ws2_32.def`: export list, generated by `build.sh` from the runner's `ws2_32.dll`. **It must match the exports of the runner's `ws2_32.dll`**
  (the shipped one is for the Highball arm64 r3 runner, `ws2_32.dll` sha256 `068aa9ca7e66828a4a10c882023fabf68d3d1727a4a04831f8a6e75879742ea5`).
- `pe.py`: PE export reader used by `build.sh`. `../../bin/pe.pl` is the Perl version (used by the install steps, because macOS ships Perl).
- `build.sh`: builds `build/ws2_32-fh6.dll` in Docker (`mstorsjo/llvm-mingw`); nothing is installed on the host. Needs Docker and `python3`.
  `./build.sh <runner aarch64-windows/ws2_32.dll> [output]`. A rebuild gives a DLL of the same size with the same 136 exports, but it is **not byte-identical** to the prebuilt one
  (we saw a different sha256, `d314b943...` vs `bd7e976b...`; the cause was not investigated, likely a newer toolchain image). Use the prebuilt file for the hash-verified install.
- Prebuilt: `../../bin/ws2_32-fh6.dll` (hash in `../../bin/ws2_32-fh6.dll.sha256`).

`ws2_o.dll` is not shipped: you make it from your own runner's `ws2_32.dll` (a copy whose internal export name is changed with
`../../bin/pe.pl rename-export`; for the r3 runner the result has sha256 `fd80e911ceddb21f5ec0e800795ff71559d5abfd39b19e0b3c9ea1e553728d4b`).
